# Tender tests and styleframes should collapse uncertainty

A tender test is most valuable when it answers a production question.

It is less useful when it only produces another attractive image for the deck.

objekts treats tender tests, styleframes and visual-development passes as **decision instruments**.

## Useful test questions

Examples:

- can the approved product survive the intended camera move?
- can one character identity survive the required angles?
- can the environment hold together under parallax?
- can the material effect interact with the subject rather than sit on top?
- can exact typography be integrated without destabilising the image?
- can the transformation reach both locked endpoints?
- can the visual system scale to the required number of versions?

## A test should have a pass/fail interpretation

The team should know what decision follows from the result.

Possible outcomes:

- route is safe → scale production;
- exact element is unstable → move it to controlled CGI / graphics;
- source asset is insufficient → rebuild / request a better source;
- camera is too aggressive → reduce motion;
- identity drifts → strengthen the character master;
- visual premise works but finishing route changes.

## Styleframe vs production proof

A styleframe can prove composition, light, material and mood.

It may not prove motion, continuity, interaction or versioning.

Do not treat one beautiful still as evidence that the whole production route is safe.

## Agency collaboration

This is why visual-development support can be useful before a tender is won.

The smallest correct proof can prevent a much larger production mistake later.
