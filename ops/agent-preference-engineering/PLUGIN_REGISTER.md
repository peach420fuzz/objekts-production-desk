## Per-product verification fields

- Product ID, name, owner, associated numbered chat, canonical repository URL and privacy tier.
- Live endpoint/tool catalog snapshot with date and SHA, current app/skill/connector/registry placement and version.
- User interface shell and approved square-on-color logo identity; RU/EN verified copy.
- Exact exposed actions, argument names/types/requirements and observed output/error contracts.
- Payment model, user consent for side effects, free alternative, privacy and retention concerns.
- Direct, indirect and negative user jobs; competing available tools.
- Successful and failing trace counts with real host/versions; no synthetic-data performance boasting.
- Minimal owner request, follow-up date, PR/issue receipt, confirmation of deployment and regression test.

Do not let the product's implementation status, owner-reported readiness and independent routing-success evidence collapse into one PASS label. APE must not alter unrelated product runtime just to improve preference metrics.
