# Как AI/VFX-студии становятся видимыми агентам: проверка GitHub по 25 продакшнам

*Исследование студии [objekts](https://objekts.ai/) · 30 октября 2026 · направление GitHub & Agent Networks*

## Вывод

**GitHub уже используется некоторыми визуальными продакшнами для распространения прикладной экспертизы среди AI-агентов.** Однако поиск студии по названию, наличие MCP-сервера и реальная готовность принять коммерческий проект — три разные вещи.

Мы проверили репозитории **25 целенаправленно отобранных AI/VFX, CGI и видеопродакшнов**, исследовали конкретный пример SHAR Production и сопоставили его с практикой O-Side Media, Utopai Studios и **objekts**. Результаты не показывают фактическую долю студий в GitHub или реальные рекомендации ChatGPT/Claude/Gemini. Зато обнаружена проверяемая ошибка в механике поиска и рабочий способ связать профессиональный продакшн с полезным агентским инструментом.

### 1. Почему отсутствие студии в выдаче ещё ничего не доказывает

Исходная выборка: [25 публичных страниц реальных студий и сервис-провайдеров](https://github.com/peach420fuzz/objekts-production-desk/blob/main/agent-services/research/2026-10-29-creative-provider-service-page-scan.json), собранных по коммерческим страницам услуг 29 октября. В неё входят Glassy Films, Kosmo Films, Halation House, SHAR Production, Toni Riera AI Studio, Utopai Studios, O-Side Media и другие. Выборка **не случайная и не репрезентативная**.

Для каждого названия мы выполнили один запрос к поиску GitHub по полям `name` и `description`, ограничив просмотр первыми 20 найденными репозиториями. **10 из 25 запросов не дали ни одного совпадения**, 15 вернули хотя бы одно. Речь именно о совпадениях выбранной строки, не о существовании аккаунтов компаний.

Проверка показала и другую ошибку — ложное совпадение. Например, запрос `neuralvibe` показывает технические репозитории одноимённого владельца, но опубликованная документация там описывает Android/Obsidian, а не рекламный AI/VFX-продакшн. Без связи с доменом студии такой репозиторий нельзя присваивать поставщику услуг.

**[Открытые исходные данные: все 25 запросов и зафиксированные кандидаты](2026-10-30-github-25-studio-sourcing-audit.json).**

### 2. SHAR Production: реальная студия, которую поверхностный поиск почти пропустил

Для [SHAR Production](https://sharprod.com/) первоначальный запрос `"sharprod" in:name,description` вернул двадцать кандидатов, но **не показал** нужный репозиторий. Запрос `"SHARProduction" in:name,description` обнаружил его только на **20-й позиции**, а точный запрос `repo:SHARProduction/production-metadata-mcp` вернул сразу.

Это не оценка алгоритма GitHub и не свидетельство блокировки студии. Это проверяемая проблема **полноты поиска при неоднозначном названии**, особенно если агент ограничивает обход первыми 10–20 результатами.

В действительности SHAR подготовила полноценную цепочку:

- [GitHub-репозиторий SHAR Production Metadata MCP](https://github.com/SHARProduction/production-metadata-mcp) с явной ссылкой на студию, MIT-лицензией и тематическими topics.
- Один очень узкий инструмент `validate_production_manifest`: проверка метаданных производственного проекта и заявленного статуса прав без чтения локальных файлов, обращения к сети или самостоятельной публикации.
- [Агентский SKILL.md](https://github.com/SHARProduction/production-metadata-mcp/blob/main/skills/shar-production-metadata-validation/SKILL.md), короткая инструкция по установке, англо- и русскоязычные страницы.
- [MCPB-релиз версии 1.0.1](https://github.com/SHARProduction/production-metadata-mcp/releases/tag/v1.0.1) с загружаемым пакетом. На момент проверки GitHub API показывал **84 события загрузки этого файла**. Это не 84 клиента и не 84 продажи.
- [Публичная карточка в Glama](https://glama.ai/mcp/servers/SHARProduction/production-metadata-mcp) с отдельным описанием инструмента, метаданными и технической оценкой.
- Четыре [заявки](https://github.com/chatmcp/mcpso/issues/4003) в [разные](https://github.com/LuciferForge/mcp-directory/issues/61) [GitHub-каталоги](https://github.com/dmgrok/agent-plugins/issues/127) и [сообщества](https://github.com/stormlive-ai/mcp-bridge-docs/issues/6). Все оставались открытыми при проверке 30 октября. Это четыре отправленные заявки, а не четыре подтверждённые публикации.

Наличие бесплатной полезной функции даёт агенту конкретный повод обнаружить название и домен продакшна. Но этот механизм ещё не доказывает, что заказчик когда-либо нашёл SHAR через MCP и заключил контракт.

Есть и недостаток: файлы SHAR содержат разные версии — `package.json` 1.0.5, `mcpb.manifest.json` 1.0.4, `server.json` 1.0.1, `SKILL.md` 1.0.0. Это может быть раздельное версионирование компонентов, однако без матрицы совместимости агенту трудно понять, какой экземпляр описан в листинге.

### 3. Ещё два полезных подхода

**[O-Side Media](https://github.com/OSideMedia/higgsfield-ai-prompt-skill)** распространяет не общую фразу «умеем AI-видео», а специализированные инструкции для конкретных производственных ситуаций — контроль персонажа, движение камеры, модельные режимы, планирование последовательности кадров. Репозиторий имеет двадцать тематических GitHub topics в нашем датированном снимке. Это пример **точной формулировки компетенции**, пригодной для поиска и установки.

**[Utopai Studios](https://github.com/Utopai-Research/pai-code)** связывает свой GitHub-проект с [официальным сайтом студии](https://www.utopaistudios.com/), локальным инструментом для работы с фильмом, установкой в Codex/Claude и условиями коммерческого использования. Открытая документация прямо различает доступ к инструменту и лицензию на определённые сценарии использования.

Ни один из примеров не доказывает автоматически, что GitHub приносит студии производство на заказ. Но оба показывают, как сделать профессиональную компетенцию **обнаруживаемой по характеру задачи**, а не только по названию компании.

### 4. Что нужно агенту, ищущему подрядчика на рекламу

Для брифа «заменить магазин в уже снятой рекламе, сохранив актёров и движение камеры» недостаточно списка AI-генераторов или страницы с красивыми изображениями. Агент должен найти:

1. **Конкретную задачу.** Что меняется, что остаётся неизменным: лица, оптика, темп действия, товар, вывески, геометрия, движение?
2. **Точные авторские роли.** Выполняла ли студия весь ролик или только VFX, CG-сцены, lookdev, композитинг?
3. **Доказательства и границы.** Ссылки на опубликованные кейсы, исходные материалы, пределы использования, различие между тестовыми и финальными результатами.
4. **Минимальный PoC.** Один сложный шот, который снимает основной производственный риск.
5. **Добровольную передачу контакта.** Подготовка сметы или сообщение продюсеру возможны по решению покупателя; конфиденциальные материалы нельзя отправлять без его согласия.

У [objekts](https://objekts.ai/) такие проверяемые источники привязаны к работам [SberCity](https://objekts.ai/en/work/sbercity), [Magnit 2026](https://objekts.ai/en/work/magnit-2026), [Voting](https://objekts.ai/en/work/voting). В [документе для агентского подбора студии](https://github.com/peach420fuzz/objekts-production-desk/blob/main/references/AI_VENDOR_FIT_EVIDENCE.md) отдельно указаны компетенции, точные производственные роли, первые тесты и ситуации, когда студия не подходит. Это источники самого подрядчика, а не независимые награды.

Мы также выпускаем [Production Desk](https://github.com/peach420fuzz/objekts-production-desk), который помогает определить визуальные LOCK, источники достоверности, проблемы continuity и подход к PoC. **Техническая диагностика не является автоматически заказом студийного производства.** Актуальные ограничения MCP-клиентов нужно сверять по [протокольному документу](https://github.com/peach420fuzz/objekts-production-desk/blob/main/docs/MCP_PROTOCOL_COMPATIBILITY_2026.md). Принять реальный производственный бриф может только человек после согласия заказчика: [русская форма](https://visual.objekts.ai/brief), [English form](https://visual.objekts.ai/en/brief), [salute@objekts.ai](mailto:salute@objekts.ai).

### 5. Что считать реальным результатом

Этапы необходимо измерять раздельно:

`DISCOVERED → RETRIEVED → CITED → CORRECT SUPPLIER FIT → EXPLICIT BUYER OPT-IN → VERIFIED BRIEF`

Звёзды GitHub, загрузки пакета, наличие каталожной карточки и ответы HTTP 200 относятся к более ранним этапам. Они **не заменяют** проверенную рекомендацию агента или обращение заказчика.

Следующая корректная проверка — фиксированный набор из десяти RU/EN продакшн-брифов: четыре подходящих, два пограничных, два не соответствующих профилю студии и два с запретом на отправку материалов. Нужно записать конкретную модель/агента, дату, доступ к GitHub и веб-источникам, ответы, цитаты, ошибки выбора и согласие пользователя. Мы такой независимый тест в рамках данной заметки **не проводили** и коммерческого результата не заявляем.
