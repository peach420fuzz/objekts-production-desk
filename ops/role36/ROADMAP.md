# OBJEKTS · 36 — Traffic & Agent Discovery
## Living roadmap · v1.0 · 25 October 2026

**Owner:** role 36. **Goal:** make [objekts](https://objekts.ai) independently discoverable to LLMs, AI agents, producers and commissioning buyers, and turn *traceably sourced* discoveries into qualified human production briefs. **Market order:** Russia → CIS → Thailand/SEA → Europe and other international markets. **Budget:** free listings and owned infrastructure; no paid directory promotion, API subscriptions or inflated promises.

This roadmap is executed against [the public syndication ledger](../../references/EXTERNAL_SYNDICATION_LEDGER_2026-10-15.md) and [the dated discovery audit](../../references/DISCOVERY_EVIDENCE_2026-10-24.md). It is **not** a separate commercial outreach CRM or a replacement for [role 12 search/AI visibility](../role12/ROADMAP.md), role 11's registry ownership, the FAKE/Production Desk product teams, or role 13 editorial. Reuse one canonical identity and one deduplicated contact history.

### ACTIVE RULES / immutable boundaries

1. **Brand and evidence:** Always write `objekts` in lower case. Official proof cases: SberCity and Magnit with correct production role/credits. Auto.ru is **development/test**, not a finished commissioned release; Stepan/Voting only when genuinely relevant. No fabricated awards, clients, contracts, performance or production capability.
2. **Studio service, not free rendering:** AI-native direction, AI/VFX, CGI, motion, compositing, animation and production engineering; no promise of conventional physical filming or free completed deliverables. Separate commercial studio work from agent tools' free diagnostic capability.
3. **Public status truth:** `DISCOVERED` / `SUBMITTED` / `OWNERSHIP_VERIFIED` / `PENDING_REVIEW` / `PUBLIC_VERIFIED` / `REJECTED` / `STALE`. Only `PUBLIC_VERIFIED` adds to external publication count. An HTTP 200 app shell alone does not prove a listing contains our record.
4. **Tests are not customers:** MCP `initialize` and `tools/list`, bot fetch, search impression, directory card, SEO audit, newsletter send and pending PR are distinct evidence types; none independently proves a buyer referral, qualified lead, acceptance or revenue.
5. **Canonical source:** first-party pages and rights/credits are authoritative; external copies must point back to the relevant case, product endpoint or published technical evidence. Never rehost private client assets or grant third parties unpublished footage.
6. **No duplicates, no spam:** check an exact company/contact/endpoint in the ledger, Gmail SENT and the destination before another submission. Revise copy for each editorial/technical audience. Respect provider rate limits; no alternate-account bypass.
7. **Zero discretionary spend:** refuse paid/featured/Verified upgrades by default; do not open subscription-backed tools or trigger paid rendering. For OAuth or legal publisher attestations requiring the owner, stop at an explicit handoff.
8. **Safe production writes:** diagnose website, DNS and Workers before edits; create only tightly scoped records and verify rollback. Do not redeploy the main site or override another role's live code.
9. **Private products stay private:** recording a remote MCP test does not publish an OpenAI/Claude app. FAKE web-image generation remains an unverified product gate; no App Directory re-submission before product owner's acceptance.
10. **Receipt discipline:** each outcome records UTC/Madrid date, exact domain/URL, action, independent response/ID, proof type, owner, follow-up date and ledger status. Never infer success from intent.

### Execution order

**Every working session (read → act → verify → update):**

1. Refresh pending/reviewed publication statuses and reply inbox, preserving existing suppression.
2. Fix highest-impact broken agent access or source mismatch with owner/issue; do not edit products managed by another role.
3. Submit/test new *free and eligible* third-party destinations or follow up with differentiated evidence-backed editorial material.
4. Independently fetch each claimed public result; record exact link, tool count or response, and the source timestamp.
5. Update this roadmap's gates, the external ledger's proof rows, and the short delta report. Carry forward blockers instead of silently replacing them with more directories.

**48-hour target:** status-check both AFS-1 reviews, four PRs and seven new editorial threads; resolve at least one actionable protocol/indexation defect *or* record precise owner issue; qualify five genuinely new free destinations with duplicate and eligibility checks.

**7-day target (targets, not promises):** 20 newly qualified outside placements/opportunities in the ledger, at least five independently verified *new* public placements if accepted by publishers, one owner-approved technical compatibility improvement, and a working source-attribution path. Do not force 20 messages to unsuitable sites.

**30-day target:** one measured RU/CIS commercial discovery experiment tied to SberCity/Magnit; split independent listings, actual agent interactions and paid leads; test whether published source pages rank/cite for buyer questions. Expand geography only when Russian/CIS buyer-intent sources and opportunities have been actively addressed.

### Priority queue by audience and offer

1. **RU / CIS production buyers:** visually specific, attributed SberCity/Magnit case studies for agencies, post houses, production designers and commissioning producers; use development-only Auto.ru for capability proof, clearly labeled.
2. **Agent-native tools and directories:** MCP endpoints, reliable metadata, skill and manifest citations; only real current functionality, repeatable acceptance checks and clear tool-use conditions.
3. **Creative professionals / VFX publications:** useful production engineering notes on continuity, material, product fidelity and real failed/solved problems; independent editors decide publication.
4. **Thailand, SEA, EU, US:** adapt exact buyer problem, language and distribution channel without inventing office, staff, clients or accolades.

### Status and handoff protocol

- Every ticket/entry has `channel | URL | exact name | owner | date | state | receipt | next action/date | notes`.
- Risk flags: `PRODUCT_UNVERIFIED`, `LEGAL_OR_APPROVAL`, `PAID_ROUTE`, `DUPLICATE`, `RATE_LIMIT`, `NO_PUBLIC_PROOF`, `CANON_MISMATCH`.
- Separate private manifests and contact credentials from public ledger; never commit API keys, magic links, draft client assets or private Plugin Creator package content.
- Product defects belong to role 34 (FAKE), Production Desk and other owning plugin streams. Site changes belong to canonical site owner. Role 36 supplies verifiable reproduction/visibility evidence and handles external distribution.
