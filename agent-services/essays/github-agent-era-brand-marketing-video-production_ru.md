# Когда заказчика представляет агент: зачем видеопродакшну GitHub

*Исследование objekts · расширенная редакция 29 октября 2026 · Рынок: B2B AI/VFX, CGI и рекламный видеопродакшн · [objekts.ai](https://objekts.ai) · Автор/издатель: **objekts***

> **English abstract.** Agentic discovery is creating a new supplier interface. For visual-production studios, public GitHub repositories can serve as versioned evidence of capabilities, credits, technical constraints and safe production-enquiry routes. New discovery infrastructure such as ARD and GitHub Copilot agent finder makes this material more relevant. Its commercial effect remains unproven until discoverability, correct matching, consent-based handoff and qualified enquiries are measured separately.

## Решение о подрядчике всё чаще начинается с описания задачи

Рекламное агентство получает бриф: городская среда в готовом ролике должна сменить сезон. Люди, движение камеры, перспективная геометрия, упаковка и монтаж остаются точными. Продюсеру нужен исполнитель для конкретного VFX-участка.

У заказчика появляется дополнительный рабочий инструмент — AI-агент. Он может прочитать бриф, составить список производственных рисков, найти потенциальных исполнителей и сопоставить публичные материалы. Иногда агенту доступны структурированные каталоги и подключённые инструменты. Иногда — только обычный веб-поиск. Заключение договора, финансовые и юридические условия и передача закрытых материалов по-прежнему требуют человеческого решения.

Для студии возникает практический вопрос: **какую информацию должен найти агент, чтобы обоснованно включить её в список подходящих исполнителей?**

Обычная главная страница отвечает на вопросы «кто вы?» и «что вы делаете?». В производственном подборе решают более точные признаки: какая часть фильма выполнена студией, какие исходники нужны, что нельзя менять, какой риск она умеет контролировать, чем это подтверждено и как передать задачу продюсеру.

Это гипотеза о новом интерфейсе покупки профессиональных услуг, которую уже можно проверять на данных и поведении реальных агентских систем.

## В 2026 году появился самостоятельный слой обнаружения возможностей

17 июня 2026 года Microsoft, Google и GitHub публично представили **Agentic Resource Discovery (ARD)** — открытую спецификацию описания и поиска агентских ресурсов. GitHub сообщил о доступности **agent finder** для Copilot: система ищет инструменты, skills, MCP-серверы и агентов в разрешённом каталоге по естественному описанию задачи. Подключение найденного ресурса остаётся отдельным решением пользователя или среды.

Google описывает две разные сущности: **каталог** публикует сведения об имеющихся возможностях, **реестр** помогает их находить и проверять. Спецификация ARD v0.91 от 26 августа 2026 года (статус *Proposal*) предусматривает для записи уникальный идентификатор, название, тип, URL или данные ресурса; для семантического поиска рекомендуются `representativeQueries` — примеры запросов пользователей.

Это заметный инфраструктурный сдвиг. Возможность должна быть описана так, чтобы поисковый слой мог её сопоставить с задачей. Затем клиент проверяет доверие, авторизацию и совместимость. В корпоративной среде действует ещё и список разрешённых ресурсов.

**Важная граница:** ARD описывает ресурсы, доступные агенту как инструменты и навыки. Услуга живой VFX-студии не превращается автоматически в исполняемый MCP-инструмент. Для профессиональной услуги необходим отдельный слой оценки применимости и согласованной передачи запроса человеку.

Источники: [Microsoft, 17.06.2026](https://commandline.microsoft.com/agentic-resource-discovery-specification-ard/); [Google Developers, 17.06.2026](https://developers.googleblog.com/announcing-the-agentic-resource-discovery-specification/); [GitHub agent finder](https://github.blog/changelog/2026-06-17-agent-finder-for-github-copilot-now-available/); [ARD v0.91](https://github.com/ards-project/ard-spec/blob/main/spec/ard.md).

## Почему GitHub оказался интересен студиям

GitHub предоставляет публично читаемые, версионированные текстовые и структурированные файлы. Можно связать описание компетенции с источником, case breakdown, ограничениями, тестами и историей изменений. Для технического агентского поиска это полезнее расплывчатого заявления о «полном цикле».

Здесь работают четыре свойства.

1. **Адресуемое доказательство.** Для кейса есть отдельный URL и точная формулировка участия. Сервисное описание может вести к исходному разбору, а тот — к официальной странице работы.
2. **Проверяемая версия.** Если меняется услуга, спецификация или ограничение, источник имеет историю и commit. Это важно для агентов, которым нужно отличать текущую возможность от старого обещания.
3. **Машинные границы.** В одном контракте можно перечислить `use_when`, `not_for`, `required_inputs`, `evidence`, `human_review_required` и условия передачи данных.
4. **Переиспользование в разных средах.** Один проверенный источник может служить основой для агентского каталога, отраслевого описания, skills и FAQ. Каждая площадка всё равно требует отдельной проверки формата, правил и реального факта публикации.

GitHub сам по себе не гарантирует индексацию у поисковой системы, попадание в реестр ARD, включение инструмента в контекст конкретной модели или рекомендацию покупателю. Публичная доступность — только первое звено.

## Есть ли прецеденты среди кино- и VFX-студий?

Да, производственные компании уже много лет публикуют техническое знание и инструменты. **Blender Studio** открыто документирует production-tested пайплайн и инструменты, выросшие из собственных анимационных проектов. **Framestore** ведёт публичную GitHub-организацию с кодовыми репозиториями и форками VFX-инструментов. Проект **OpenMontage** публикует открытое агентское видеопроизводство с пайплайнами, инструментами и примерами получаемых фильмов.

Это три разных типа публичного присутствия:

| Пример | Что можно проверить | Что из этого не следует |
|---|---|---|
| [Blender Studio](https://studio.blender.org/tools/) | Документированные инструменты и production pipeline | Что любая внешняя рекламная заявка автоматически попадёт в студию |
| [Framestore GitHub](https://github.com/framestore) | Публичные инженерные репозитории/форки | Что профиль является агентским каталогом коммерческих услуг |
| [OpenMontage](https://github.com/calesthio/OpenMontage) | Open-source agentic video workflow с опубликованными примерами | Что это сопоставимая услуга живого бутикового VFX-подрядчика |

Из этих примеров можно сделать узкий вывод: публикация производственных методов на GitHub давно существует. **Проверенных массовых прецедентов именно модели «компетенции студии → кейсы → fit брифа → согласованный human handoff» в этой небольшой выборке нет.** Это не доказательство уникальности objekts: для такого утверждения потребовалась бы гораздо более широкая перепись рынка и действующих агентских каталогов.

Сама рыночная ниша выглядит проверяемой: профессиональная студия может публиковать агенту понятную поверхность услуг, сохраняя человеческий контроль над производством, правами, сроками и сметой.

Публичная карточка, успешный `tools/list` и работающий продюсерский intake — разные события. В опубликованных источниках **нет подтверждённой цепочки «агент нашёл студию → заказчик передал бриф → продюсер квалифицировал запрос → заключён договор»**. Поэтому коммерческий эффект присутствия objekts в агентских сетях пока **не установлен**.

Самый интересный результат эксперимента — уже обнаруженная разница между четырьмя слоями: публикацией данных, нахождением записи, корректным вызовом инструмента и коммерческим результатом. По отдельности их можно измерять. Их объединение в один показатель «агентского маркетинга» уничтожает информацию о том, где именно теряются заказчики.

### Производственный подбор на примере SberCity

Пусть агент ищет подрядчика по запросу: «Существует ролик с реальными актёрами. Нужно сделать новогоднее состояние городской среды, сохранив камеру, физический контакт, архитектуру и монтаж».

Применимое доказательство — опубликованная роль objekts в AI VFX/графике SberCity. Следующий шаг агента — определить три группы ограничений:

1. **Источник:** есть ли утверждённые plates, референс архитектуры, положение камеры и правила сохранения актёров?
2. **Сложность:** где самый рискованный контакт актёра со снегом, пересечение с архитектурой, динамическая окклюзия или световая непрерывность?
3. **Приёмка:** какой один PoC должен показать, что перспективу, масштаб, актёра и среду удастся сохранить на движении?

Только после этого обоснован вопрос, нужен ли агентству разговор с продюсером objekts. Правильный результат предварительного подбора — **конкретная проверяемая гипотеза производства** и добровольный маршрут контакта. Агент ещё не знает согласованной сметы, доступности команды и финальных условий прав.

### Что здесь обнаружилось о маркетинге

Разборы отличаются по производственному масштабу. Tic Tac доказывает работу на уровне одного краткого шота; SberCity — сохранение мира и среды между планами; Magnit — сопряжение снятого материала с реконструированным пространством; Voting — задачу последовательности персонажа и его состояний. Простая маркировка всех четырёх как «генеративное видео» теряет различия, по которым продюсер выбирает исполнителя.

Из этого следует рабочее требование к агентскому каталогу студии: каждый кейс должен иметь **task signature** — тип задачи, авторитетные исходники, основные отказные сценарии, условия применимости, точную роль студии, статус результата, минимальный тест и границу прав.

Для objekts это следующий этап развития публичной документации. Источники и первые сервисные описания уже существуют. Проверить их на реальных системах выбора подрядчиков ещё предстоит. На момент этой статьи мы не заявляем, что конкретный агент включил objekts в shortlist по этим четырём кейсам или передал оплаченный заказ.

## Как должна выглядеть машиночитаемая услуга видеопродакшна

Возьмём один из реальных производственных сценариев.

**Запрос:** «Нужно заменить архитектурное окружение в уже снятой рекламе; актёры и камера должны остаться без изменений».

Для подбора исполнителя полезна следующая карточка:

```yaml
service: "AI/VFX shot finishing"
provider: "objekts"
use_when:
  - "Existing filmed plate needs a controlled environment transformation"
  - "Camera, actors, timing and product identity must remain stable"
required_inputs:
  - "Approved plate and rights to use it"
  - "Shot duration, final formats and intended channels"
  - "Immutable visual/camera/brand constraints"
evidence:
  - title: "Magnit — hybrid VFX"
    url: "https://objekts.ai/en/work/magnit-2026"
    source_type: "first-party case"
not_for:
  - "Physical filming crew and location production"
  - "Unlicensed footage or identity modification"
human_review_required: true
auto_submit_client_material: false
```

Это **иллюстративная схема для статьи**, не объявление действующего API и не официальный ARD-манифест. Для реестра понадобится действующий schema adapter, проверка конформности и разрешение владельца ресурса.

Покупателю нужны дополнительные поля: какие задачи оцениваются только после PoC, сколько версий предполагается, что считается QC и где заканчивается публичная автоматическая диагностика. Пример подходящего доказательства — [Magnit 2026](https://objekts.ai/en/work/magnit-2026) с указанным вкладом в hybrid VFX и отдельным статусом разработочных материалов. Кейс должен доказывать конкретную компетенцию, а не принадлежность студии ко всей съёмочной группе.

## Пять выводов для агентств, брендов и продакшнов

### 1. Единицей продвижения становится производственная задача

Термины «AI video», «CGI» и «full service» слишком широки для точного подбора. Агенту полезнее различать: замена окружения в plate, сохранение лица в серии, продуктовая геометрия, сложный композитинг, full-film художественная разработка, lookdev и R&D. Каждому типу нужен собственный набор критериев, ограничений и доказательств.

**Следствие для маркетинга:** начинать описания услуг с реального сценария заказчика и стоимости ошибки, которую предотвращает производство.

### 2. Кейс становится техническим доказательством при соблюдении credits

Случай, когда студия сделала один product VFX shot внутри чужого ролика, ценен для соответствующего брифа. Корректное указание роли позволяет использовать этот опыт в профессиональном выборе. Разделение `released`, `commissioned`, `development` и `R&D` исключает ошибочные обещания.

**Следствие:** у каждого public case должен быть машиночитаемый паспорт: `project_id`, `exact_credit`, `status`, `problem`, `method`, `acceptance`, `rights`, `canonical_url`.

### 3. В агентском поиске появляются собственные точки отказа

Пользователь может вообще не получить нужную карточку; агент может ошибиться в семантическом совпадении; реестр может содержать устаревший endpoint; подключение может не поддерживать версию протокола; механизм передачи брифа может требовать согласия и NDA. Исправления на каждом этапе различаются.

**Следствие:** проверять discovery, selection, compatibility, source quality и безопасный handoff как независимые системы.

### 4. Коммерческий контакт должен быть добровольным и предметным

Задача профессионального агента — помочь принять решение. Публичная документация должна позволять сначала получить полезную диагностику и обоснование. Если заказчик готов обсудить реализацию, агент спрашивает до трёх недостающих фактов и предлагает существующий путь связи с продюсером. Закрытые материалы передаются только через согласованный канал и после необходимого согласия.

**Следствие:** количество показанных ссылок на бриф не является количеством брифов. Количество отправленных форм не является количеством квалифицированных проектов.

### 5. Нужна новая аналитика — от намерения до человеческого подтверждения

Практичная воронка:

| Уровень | Метрика | Нужное доказательство |
|---|---|---|
| Availability | Ресурс публично доступен | URL, содержимое, дата проверки |
| Discovery | Агентский реестр действительно находит запись | Запрос, реестр, ответ, версия |
| Fit | Агент правильно рекомендует/исключает компетенцию | Набор positive/negative запросов и оценка |
| Referral | Пользователь сам перешёл к контакту или указал источник | Согласованный referral/самоатрибуция |
| Qualified enquiry | Продюсер получил и оценил реальный бриф | Минимальная защищённая запись и receipt |
| Revenue | Проект согласован или оплачен | Авторизованный коммерческий учёт |

Между этими уровнями нет гарантированного перехода. Именно отношение квалифицированных обращений к корректным агентским совпадениям покажет, создаёт ли новый канал коммерческую пользу.

## Что проверять в ближайшие 30 дней

Для одной студии достаточно небольшого честного эксперимента — при наличии разрешений на необходимые тесты:

1. Описать четыре услуги в едином формате: AI/VFX shot, AI-native commercial, product CGI/lookdev, visual R&D. Каждой дать positive, near-miss, negative и consent/rights сценарии.
2. Проверить минимум четыре актуальных кейса на exact role, release stage, активные canonical ссылки и допустимость использования публичных медиа.
3. Подготовить по 40 контролируемых запросов для каждого разрешённого агента/хоста, фиксируя модель, дату, подключённый каталог, prompt, результаты и ложные совпадения.
4. Сравнить **контроль без структурированной карточки** с новой карточкой на одинаковых запросах. Изменения metadata фиксировать по одному.
5. Отдельно проверять, обнаруживаются ли записи при семантическом запросе, проходит ли соединение и остаётся ли путь к продюсеру полностью добровольным.
6. Публикацию на дополнительных площадках проводить через их реальные правила; считать только подтверждённые live URL и реальную атрибуцию обращений.

Это план эксперимента, а не заявление о выполненных тестах или достижимых цифрах конверсии.

## Заключение

Появление ARD и agent finder показывает, что обнаружение возможностей становится самостоятельной задачей инфраструктуры AI. Для агентств и производственных компаний открывается новая поверхность коммуникации: доступные агентам, проверяемые описания того, какую профессиональную работу можно поручить конкретному исполнителю.

GitHub подходит на роль публичного доказательного слоя. Здесь можно хранить компактные паспорта услуг, разборы кейсов, методологии, версии, негативные сценарии и ссылки на человеческий процесс закупки. В развитии этой модели коммерчески важным показателем станет **доля запросов, правильно сопоставленных с реальной компетенцией и дошедших до квалифицированного разговора с продюсером**.

Пока objekts может подтвердить подготовленную инфраструктуру и ряд фактических внешних публикаций. Следующий этап — измерить, приводит ли эта доступность к правильному выбору и реальной работе. Это проверяемая, открытая исследовательская задача для студии и для рынка.
